How this codebase is put together

Billing ERP is a Next.js App Router frontend talking to a separate Express + MySQL API. Features live in folders, not scattered pages. If you learn one module, you can ship the next.

Overview

The UI in this repo is the product surface: dashboards, forms, POS, document preview, tenant branding. Business data is owned by a backend API (not committed here). The browser authenticates with Firebase, then every API call sends a Bearer token. Tenants are resolved on the server from that token.

Rule of thumb: pages are thin. Real logic sits under src/features/<name>/ — types → repository → service → hooks → UI.

Feature module anatomy

Most ERP modules follow the same shape. Expenses and Enquiries are the cleanest recent examples. 

src/features/expenses/
  types.ts                         # domain types + constants
  repository/expenses.repository.ts  # raw apiRequest paths
  services/expenses.service.ts     # normalize MySQL quirks (0/1 → bool)
  hooks/use-expenses.ts            # React Query keys + mutations
  components/expenses-dashboard.tsx
  addform/
    expense-form-sheet.tsx
    expense-categories-dialog.tsx

What each layer does

FileResponsibilityDoes not
types.ts Shapes shared by UI and API contract Fetch or render
*.repository.ts HTTP only: path, method, JSON body via apiRequest UI state, caching
*.service.ts Map/normalize API payloads (numbers, dates, booleans) Call React hooks
hooks/use-*.ts Query keys, useQuery / useMutation, invalidation Own JSX
components/ Dashboards, tables, KPIs, empty states Hardcode fetch URLs
addform/ Create/edit sheets, dialogs, pickers Own the list page layout

The matching page is usually one liner, e.g. src/app/(dashboard)/dashboard/expenses/page.tsx → <ExpensesDashboard />.

Request flow

UI (dashboard / form)
  → hook (useCreateExpense)
    → service (normalize in/out)
      → repository (POST /expenses)
        → apiRequest (Firebase token + NEXT_PUBLIC_API_BASE_URL)
          → Express API (tenant_id from auth)
            → MySQL

Mutations invalidate a feature query key namespace (e.g. ["expenses"]) so lists and summaries refresh together. Prefer that over manual refetch in every button handler.

Auth & API

src/lib/api.ts is the only place that should assemble API URLs and auth headers for JSON endpoints.

  • Waits for Firebase user (waitForAuthUser)
  • Attaches Authorization: Bearer <idToken>
  • Expects { success, message?, data } envelopes
  • Throws ApiError with status + server message
Backend lives outside this repo (Express on your server). Mount routes like /expenses, /enquiries, /vendors there. Frontend never talks to MySQL directly.

Tenant

src/features/tenant/ loads business profile, logo, and document branding. Rows from the API are scoped with tenant_id — never hardcode a business id in the UI.

Routes & navigation

  • src/components/layout/navigation.ts — contextual side menus per module
  • src/components/layout/top-navigation.tsx — primary module list + search
  • src/lib/erp-search.ts — “Search modules…” destinations
  • URL params for filters: useUrlSearchParam, useUrlParam("filter"), ?create=1 to open forms

Deep links matter for sales demos and support. Prefer /dashboard/expenses?filter=unpaid over local-only filter state when it is shareable.

UI conventions

  • Money: en-IN + INR / ₹ — not USD.
  • Empty lists: shared EmptyState (centered icon, title, optional CTA).
  • Forms: sheets for create/edit on list pages; full routes for long documents (/invoices/new).
  • Theme: primary is near-black (#111827), muted gray text, 0.75rem radius. Avoid inventing a second visual system.
  • POS: somewhat separate CSS under src/features/pos/ — treat it as its own product surface.

Checklist: add a new module

  1. Create src/features/<name>/ with types, repository, service, hooks, dashboard, forms.
  2. Add src/app/(dashboard)/dashboard/<name>/page.tsx.
  3. Wire sidebar in top-navigation.tsx and menus in navigation.ts.
  4. Register search target in erp-search.ts.
  5. Optionally surface a KPI on the main dashboard page.
  6. Implement matching Express routes + MySQL tables on the API server (tenant-scoped).
  7. Use EmptyState for zero-data; keep INR / en-IN formatting.

Environment

Local frontend expects at least:

NEXT_PUBLIC_API_BASE_URL=https://your-api.example.com
# plus Firebase web config used by src/firebase/config.ts

Never commit secrets. .env.local stays on the machine. API keys for Firebase Admin belong on the Express host, not in this Next app.
